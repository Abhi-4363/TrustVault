## 1. Quickstart From a Clean Clone

To run TrustVault locally on any machine with Node.js (`v18+` or `v22+` recommended) and npm:

### Step 1: Clone the Repository
```bash
git clone https://github.com/Abhi-4363/TrustVault.git
cd TrustVault
```

### Step 2: Configure Environment Variables
Copy the provided `.env.example` templates to `.env`:
```bash
# Backend environment setup
cp backend/.env.example backend/.env

# (Optional) Frontend environment setup
cp frontend/.env.example frontend/.env
```

The default values in `backend/.env.example` are pre-configured for local development with zero external dependencies. If MongoDB Atlas is not running locally, TrustVault automatically falls back to an in-memory repository, allowing the full application to run instantly.

### Step 3: Install Dependencies & Seed Demo Data
```bash
# 1. Install and seed backend
cd backend
npm install
npm run seed     # Populates demo accounts (Admin, Owner, Viewer) and sample files

# 2. Install frontend
cd ../frontend
npm install
```

### Step 4: Start Development Servers
Open two terminal windows:

**Terminal 1 (Backend API - Port 5000):**
```bash
cd backend
npm run dev
```

**Terminal 2 (Frontend Client - Port 5173):**
```bash
cd frontend
npm run dev
```

Visit `http://localhost:5173` in your browser.

## 4. Production Cloud Deployment (Render Blueprint)

TrustVault includes a ready-to-use `render.yaml` blueprint for automated deployment on [Render](https://render.com):

1. **Connect GitHub**: Push the repository to GitHub and log in to Render.
2. **New Blueprint**: Click **New +** -> **Blueprint**.
3. **Select Repository**: Select `TrustVault`. Render automatically detects `render.yaml`.
4. **Configure Secrets**:
   - `MONGODB_URI`: Your MongoDB Atlas cluster connection string.
   - `JWT_SECRET`: A secure random 32+ character string (auto-generated by Render).
   - `CLIENT_URL`: `https://trust-vault-9185.vercel.app` (your deployed frontend URL without trailing slash).
   - `EMAIL_PROVIDER`: Set to `brevo` (recommended for Render), `resend`, or `smtp`.
   - `BREVO_API_KEY`: Brevo API key (from https://app.brevo.com/settings/keys/api). Communicates via HTTPS over Port 443 (Render compatible).
   - `EMAIL_FROM`: Sender address (e.g. `konagallaabhiram@gmail.com`). **Must be verified in Brevo under Senders & IP**.
5. **Persistent Disk**: The blueprint provisions a 10GB persistent disk mounted to `/opt/render/project/src/backend/storage/uploads` to ensure uploaded binaries persist across container redeploys.
6. **Deploy**: Click **Apply**. Render will build the Vite SPA and launch the Express API service with automated health checks.
